## Overall Impression

A smaller, correctly-themed internal ops tool that inherited its sibling's brand tokens faithfully but not its solved UX patterns — sortable/searchable tables, icon-grouped nav, confirm-before-destroy all exist next door in product/web and weren't ported here. The biggest gap is safety, not polish: irreversible, business-critical actions (revoking a customer's license, decommissioning a deployment) fire on a single click with a component built for exactly this guard sitting unused in the same codebase.

## What's Working

1. **`src/components/secret-reveal.tsx`** — the one-time secret reveal (license JWT/heartbeat token) is genuinely well designed: destructive warning that it's shown once, copy-with-confirmation, scrollable monospace box. The one high-consequence moment that got real care.
2. **`src/app/login/login-form.tsx`** — correct htmlFor/id associations, aria-invalid/aria-describedby wired to real per-field errors, proper autoFocus/autoComplete, disabled+pending submit state. Textbook accessible form.
3. **Token fidelity with product/web** — globals.css is byte-for-byte the same OKLCH palette/font/radius as the sibling app. Brand consistency across the two apps is solid.

## Priority Issues

**[P0] No confirmation on irreversible, business-critical status mutations — despite the fix already existing unused in the codebase**
- Why it matters: Revoke (documented as "terminal" in its own file), Decommission, and Deactivate all mutate on a single click/select with zero guard. A mis-click on a paying customer's license has no safety net.
- Fix: wrap these actions in the already-built `<ConfirmActionButton>`, currently imported nowhere.
- Files: licenses/status-buttons.tsx, deployments/status-select.tsx, customers/status-toggle.tsx, plans/active-toggle.tsx, components/confirm-action-button.tsx
- Suggested command: `/impeccable harden`

**[P1] No loading.tsx/error.tsx/not-found.tsx anywhere in the route tree**
- Why it matters: any backend hiccup or a bad customer/deployment ID throws straight into Next's unstyled default crash page — jarring for ops staff mid-incident. Skeleton is installed and unused.
- Fix: add a shared error.tsx under app/dashboard/ and per-route loading.tsx using the existing Skeleton.
- Suggested command: `/impeccable harden`

**[P2] Zero search/filter/sort/pagination on any list page**
- Why it matters: directly undercuts the "triage many customers/tickets fast" job this app exists for. The sibling app documents a shared sortable/searchable DataTable built for exactly this that was never ported here.
- Files: customers/page.tsx, licenses/page.tsx, deployments/page.tsx, support/page.tsx
- Suggested command: `/impeccable polish`

**[P2] Repeated row controls have no per-row accessible name**
- Why it matters: a screen reader hears "Revoke, button... Revoke, button..." N times with no row context — compounding the P0 risk for a keyboard/screen-reader user.
- Fix: add aria-label naming the specific row, e.g. `Revoke license ${licenseNumber}`.
- Files: licenses/status-buttons.tsx, deployments/status-select.tsx, support/ticket-actions.tsx, plans/active-toggle.tsx, customers/status-toggle.tsx

**[P3] Installed-but-dead primitives and duplicated card markup**
- Why it matters: Card and Skeleton are installed, never imported; the same `rounded-lg border border-border p-4` div is repeated 12+ times instead. Two people will independently "fix" the same visual treatment differently.
- Fix: replace repeated divs with Card; wire up or delete Skeleton/ConfirmActionButton.

## Persona Red Flags

**Alex (ops power user, triaging fast)**: No search/sort/filter anywhere — every lookup is manual scroll-and-scan. The Licenses page's dual status/state fields force cross-referencing two badges per row mid-incident. Deployment heartbeat table has no sort-by-recency; a degraded run just turns text red inline, easy to miss while scanning. No bulk actions on support tickets — every row is a separate round trip.

**Sam (screen reader / keyboard-only)**: Repeated unlabeled row controls across every status-changing button/select. Table headers render bare `<th>` with no scope="col". No confirmation step means no "are you sure" checkpoint to catch a wrong-row activation from keyboard nav — exactly the scenario confirmation dialogs exist to prevent. (Login form and the dialog close button are both done correctly — Sam is well served there specifically.)

## Minor Observations

- Sidebar has zero icons despite Lucide being installed and used elsewhere — a visible register mismatch versus the sibling app's icon-grouped nav, even with only 6 items here.
- Dashboard KPI cards show raw counts with no trend/delta, unlike the sibling's delta-badge convention — reasonable for a first pass, but the primitive already exists next door.
- Date formatting is inconsistent: raw ISO slice in one place, toLocaleString() in another, within the same app.
- Two files duplicate a near-identical status-to-badge-variant ternary inline instead of sharing one function.
- Deployments page's "Registry and health status only — no remote restart/update actions" is good, honest scope-setting copy; more of this would help near Revoke specifically.
